# Drip ChatGPT SEO Plugin — V0.1

This project turns the **existing local Drip/MrShopPlus automation** into a ChatGPT-usable MCP app/plugin.

The design is deliberately asymmetric:

- **ChatGPT** = Exact Entity / SKU research, web + image reasoning, V4.4 decision input.
- **MCP server** = narrow, auditable tool boundary.
- **Existing local Agent** = the workflow you already have: MrShopPlus API calls, V4.4 generation/validation, save/publish, backend read-back, storefront acceptance, progress checkpoints.

The MCP layer does **not** duplicate your working automation.

## Architecture

```text
ChatGPT
  ├─ web/image research → Exact Entity + SKU verdict
  └─ Drip SEO plugin tools
       ↓
Streamable HTTP MCP (/mcp)
       ↓
Local Agent bridge (127.0.0.1:8787 by default)
       ↓
Existing MrShopPlus API workflow
       ↓
prepare → immutable plan_id → execute → verify
```

The product flow intentionally has no direct `update_product(fields...)` tool. ChatGPT can only execute a `plan_id` generated by the local V4.4 dry run.

## Tools exposed to ChatGPT

### Product/PDP

- `search_products` — read-only candidate search.
- `get_product_context` — read-only product snapshot for ChatGPT research.
- `get_product_images` — returns actual MCP image content for ChatGPT Vision.
- `prepare_product_v44` — read-only dry run; requires structured Exact Entity/SKU evidence.
- `execute_product_v44` — write action; accepts only `product_id + plan_id`.
- `verify_product_v44` — read-only backend + storefront acceptance.

### Category/collection

- `search_categories`
- `get_category_context`
- `prepare_category_seo`
- `execute_category_seo`
- `verify_category_seo`

### Batch

- `get_run_status`

## SKU gate

`prepare_product_v44` accepts only three verdicts:

- `VERIFIED_SKU`
- `SKU_OMIT`
- `HOLD`

For `VERIFIED_SKU`, the MCP server requires at least one Tier 1–4 evidence record that explicitly carries the same SKU and has `exact_entity_match=true`.

The bridge rejects known internal/placeholder identifiers, including the 15-digit MrShopPlus Product ID pattern already observed in the current storefront Schema.

This is intentionally stricter than “the model thinks it is probably correct.”

## 1. Install

```bash
npm install
cp .env.example .env
```

Edit `.env` and point `LOCAL_AGENT_BASE_URL` at your already-running local Agent bridge.

## 2. Map the existing local workflow

Read [LOCAL_AGENT_CONTRACT.md](./LOCAL_AGENT_CONTRACT.md).

If your existing Agent already has HTTP routes, set the `AGENT_*_PATH` environment variables to those routes.

If the existing Agent is currently invoked in-process or by CLI, add a tiny HTTP adapter implementing the contract; do **not** rewrite the working MrShopPlus workflow.

## 3. Test without touching MrShopPlus

Terminal A:

```bash
cp .env.example .env
npm run mock-agent
```

Terminal B:

```bash
npm start
```

Health check:

```bash
npm run smoke
```

MCP Inspector:

```bash
npx @modelcontextprotocol/inspector
```

Choose **Streamable HTTP** and connect to:

```text
http://localhost:8000/mcp
```

The mock includes one LV Footprint Soccer record so you can exercise the Product-ID-vs-SKU guard without a production write.

## 4. Connect to ChatGPT for private development

ChatGPT connects to **remote MCP**, not directly to localhost. For a local/private server, use OpenAI Secure MCP Tunnel (or another approved development tunnel) and register the resulting HTTPS `/mcp` endpoint in ChatGPT developer mode.

The private topology should stay:

```text
ChatGPT → secure tunnel → local MCP :8000 → local Agent :8787 → MrShopPlus
```

The local Agent itself does not need to become publicly reachable.

## 6. Intended ChatGPT workflow

Example user prompt:

```text
Find all Louis Vuitton LV Footprint Soccer products, resolve Exact Entity and SKU with evidence, then execute SEO-PDP V4.4. HOLD anything you cannot prove.
```

Expected orchestration:

```text
search_products
→ get_product_context
→ get_product_images
→ ChatGPT web/image research
→ VERIFIED_SKU / SKU_OMIT / HOLD
→ prepare_product_v44
→ review PASS/diff
→ execute_product_v44
→ verify_product_v44
```

For category pages:

```text
search_categories
→ get_category_context
→ ChatGPT research
→ prepare_category_seo
→ execute_category_seo
→ verify_category_seo
```

Category pages must not inherit PDP-only SKU/Product Details/Product-schema requirements.

## 7. Production security

- Keep `LOCAL_AGENT_BASE_URL` private.
- Use a long random `LOCAL_AGENT_TOKEN`.
- Do not log MrShopPlus credentials/cookies/tokens in MCP results.
- The local Agent must authorize every write and reject stale/mismatched `plan_id` values.
- Keep write tools plan-based; never expose generic browser clicks or arbitrary API payload pass-through.
- This V0.1 exposes no delete tool.
- For a public plugin, use a stable public HTTPS MCP endpoint plus the authentication/authorization method required by the current OpenAI plugin review rules. A temporary or Secure MCP Tunnel alone is for development, not public submission.

## 8. Current account/product limitation

As of 2026-09-18, OpenAI documents full custom-MCP write/modify support for ChatGPT Business and Enterprise/Edu. Plan/surface availability can change. The server/plugin package is built for the full read+write MCP flow; if your current ChatGPT account does not expose private write-capable custom MCP connections, the code can still be tested with MCP Inspector/local clients and is ready for an eligible ChatGPT workspace or later public plugin submission.

## Files to adapt first

You should need to change only two things initially:

1. `.env` — existing local Agent URL/token/route mapping.
2. Your local Agent bridge — map the routes in `LOCAL_AGENT_CONTRACT.md` to the workflow that already produced your successful V4.4 runs.

Do not rewrite the underlying MrShopPlus automation unless its current API surface cannot be cleanly adapted.
