# 墨菲定理抗性审查报告

**对象**：dripsneakers.org `Gucci-Sneakers` 分类 27 款未上架商品 → SEO-PDP V4.4「生成 + 写入 + 上架」
**审查原则**：凡可能出错，终将出错（Anything that can go wrong will go wrong）
**审查日期**：2026-09-23
**分支**：`feature/gucci-sneakers-pdp-v4.4`

---

## 0. 审查方法与分级

每条失效点给出五元组：

```text
失效模式 → 触发条件 → 后果 → 防御 → 检测方式
```

**分级依据不是"发生概率"，而是"发现难度"。**

| 级别 | 定义 | 为什么危险 |
|---|---|---|
| **P0** | 静默失败：不报错、看起来成功、错误进入生产 | 无告警，靠人工肉眼才能发现 |
| **P1** | 显式失败或局部错误：会返工 | 有信号 |
| **P2** | 可容忍或可后补 | — |

**本次审查的核心结论：这个任务最危险的部分不是"写不进去"，而是"写进去了、看起来完美、但优化的是错误的产品"。** V4.4 §27 第一条铁律就是「Do not optimize the wrong product」——而 27 款里有 15 款的商品名称是**纯供应商 SKU 串**（`Gucci Screener 546551 99W20 4368`），实体信息为零。

## 2. P0 失效清单（静默失败）

### A1 — 实体误判：优化了错误的产品 【最高危】

| 项 | 内容 |
|---|---|
| **失效模式** | 15 款 Screener 名称为纯 SKU 串，无颜色名/图形描述。若把 #3 的实体误认为 #4 的实体（配色搞反），SEO 全部正确但指向错误商品 |
| **触发条件** | 仅靠名称/SKU 猜颜色；或仅靠单一来源（Tier 5/6）确认 |
| **后果** | **不可自我修复**。页面看起来"完整专业"，实则 V4.4 §27 第一铁律被违反。且 15 款互相污染，错误会成片 |
| **防御** | 三重交叉：①图片配色实读；②SKU 与图片配色一致性；③Tier 1–4 来源（Gucci 官方 / StockX / GOAT）颜色名独立确认。任一冲突 → `HOLD` |
| **检测** | 每款产出「SKU ↔ 图片 ↔ 来源颜色名」三方对照表，三者不一致即拦截 |

**已识别的具体风险样本**：#13 `577684 2C830 7266`（主图为黄绿红 Web + 生胶底）、#14 `677423 9SFR0 2587`（粉绿 Web + 粉底粉跟）、#15 `577684 2C830 9150`（粉绿 Web + 生胶底白跟）。三者配色极近但**不同**，是误判高发区。

### A2 — SKU 与图片配色不一致（供应商上传错图）

| 项 | 内容 |
|---|---|
| **失效模式** | 文件名错乱（已知 F11），但**内容也可能错**——我只验证了图与**名称**一致，未验证图与 **SKU** 一致。若供应商把 A 配色的图挂到 B 的 SKU 下，Colorway 描述必错 |
| **触发条件** | 直接信任主图作为配色依据 |
| **后果** | Colorway / Graphic 写错，Meta Description 里的实体识别信息错 |
| **防御** | 用 Tier 1–4 来源的**该 SKU 官方配色名**反查图片；图片无法与官方配色对上的 → `HOLD` |
| **检测** | 「SKU → 官方配色名 → 图片」反查表 |

### A3 — 关键词自相残杀（Cannibalization）

| 项 | 内容 |
|---|---|
| **失效模式** | 15 款 Screener 高度相似，若 Meta/H1 仅换 SKU 串，Google 判为重复内容，**同一组关键词下多页面互相压制** |
| **触发条件** | 描述模板化，Colorway/图形差异未真实表达 |
| **后果** | 上架了但排名互相稀释，等于白做 |
| **防御** | 每款的 Colorway + 图形描述必须**真实不同**（依赖 A1/A2 解决）；SEO Title 含唯一 SKU；Title 长度分散 |
| **检测** | 27 条 Title / Meta 两两相似度计算，超阈值告警 |

### A4 — 供应商话术与违禁表述泄漏

| 项 | 内容 |
|---|---|
| **失效模式** | `Pkgod` / `Perfect Kicks` / `1:1 exact copies` / `high-quality replica brand` 若漏进新内容，违反 V4.4 unsupported-claim guard，且构成平台与法律风险 |
| **触发条件** | 复用旧 Content 片段；或"参考原文改写"时带入 |
| **后果** | 合规风险；V4.4 §9 硬规则违规 |
| **防御** | 写入前对**全部待写字段**跑黑名单正则：`pkgod|perfect\s*kicks|1:1|replica|best quality|authentic quality|guaranteed`（大小写不敏感）；命中即阻断 |
| **检测** | 阻断式扫描（非告警式） |

### A5 — 废弃域名死链残留

| 项 | 内容 |
|---|---|
| **失效模式** | 25 款 Content 含 `dripsneakers.net` 链接。若只改关键描述、未整体替换 `Content`，死链留在前台 |
| **触发条件** | 局部更新而非整体替换 |
| **后果** | 前台出现指向废弃域名的外链 |
| **防御** | `Content` **整体替换**为图片流；替换后扫描 `dripsneakers.net` 残留 |
| **检测** | 写入后读回扫描 `Content` 是否含 `.net` |

## 3. P0 失效清单（机制类）

### B3 — 上架开关 Vue 异步 → 状态翻回（最阴的一条）

| 项 | 内容 |
|---|---|
| **失效模式** | skill 记载：点击上架开关后**立即读回仍是旧值属正常**。若据此判定"点击失败"而**重复点击**，第二次点击会把已开启的开关**关回去** |
| **触发条件** | 脚本含重试逻辑且以"立即读回"为判据 |
| **后果** | 27 款最终仍为未上架，但每款都"写入成功"——**静默失败** |
| **防御** | **禁止以 click 后即时读回作为判据**；以「保存后重新加载表单」的 `IsShow` 为准；开关只点一次 |
| **检测** | 批处理后重读分类 `showCount`，必须 = 9 + 本轮上架数 |

### B1 — TinyMCE 编辑器错位

| 项 | 内容 |
|---|---|
| **失效模式** | `editor[0]`/`editor[1]` 映射仅在 #1 实测。若某款结构不同（如缺关键描述区、多出第 3 个编辑器），内容写入错误字段 |
| **触发条件** | 硬编码 `editors[0]`/`editors[1]` 索引 |
| **后果** | 商品描述被塞入 PDP 文本（或反之），前台结构与 V4.4 不符 |
| **防御** | **每款写入前重新枚举** editors 并校验容器文案（`商品描述` / `关键描述`），用文案而非索引定位 |
| **检测** | 写入前断言 editors 数量=2 且文案匹配，不匹配即跳过该款 |

### B2 — SEO 弹窗「吞词」静默失败

| 项 | 内容 |
|---|---|
| **失效模式** | skill 记载：每次进入弹窗后**第一个关键词必被吞**。表现为关键词少 1 个，**不报错** |
| **触发条件** | 写入关键词后未校验标签数 |
| **后果** | SEO Keywords 缺项，V4.4 §8 不完整 |
| **防御** | 写后**读标签列表与预期逐一比对**，不一致则整轮重建（≤3 次），仍不一致则**中止该款且不保存** |
| **检测** | 弹窗确认前的标签全等断言 |

### B4 — `saveModify` payload 漏字段清空他字段

| 项 | 内容 |
|---|---|
| **失效模式** | 若绕过 UI 直接构造 payload，漏字段可能被平台按"空值覆盖"，清掉价格/库存/尺码 |
| **触发条件** | 手写 API payload |
| **后果** | 价格归零、库存丢失（与 E1 叠加） |
| **防御** | 优先走 UI（skill 路径）；如走 API，必须**先读全字段再整体回写**；写入前后 diff 非目标字段 |
| **检测** | 逐款 diff `BasePrice/MarketPrice/Attrs/Stk` 是否变化 |

### B5 — 批量断点导致状态不一致

| 项 | 内容 |
|---|---|
| **失效模式** | 写到第 20 款时会话超时/浏览器崩溃，前 19 款已写、后 8 款未写 |
| **触发条件** | 单次长任务无检查点 |
| **后果** | 批次状态不明，重复写入或漏写 |
| **防御** | 逐款落盘进度文件（`written.json`）；幂等（可安全重跑）；分批（建议 ≤7 款/批） |
| **检测** | 每批结束后重读后台，与进度文件核对 |

### B6 — 并发写入覆盖

| 项 | 内容 |
|---|---|
| **失效模式** | 同一提示词被同时派给其他代理，两进程写同一商品 |
| **触发条件** | 用户多设备/多代理并行 |
| **后果** | 内容互相覆盖，最终状态不可预测 |
| **防御** | 写入前检查 `ModifyTime` 是否在预期窗口内；发现异动立即停手 |
| **检测** | 写入前后 `ModifyTime` 连续性 |

## 4. P0 失效清单（分类与 URL）

### C1 — 新名称掉出自动分类 【极高危，且完全隐蔽】

| 项 | 内容 |
|---|---|
| **失效模式** | 分类成员由条件动态计算：`Name LIKE '%Gucci%' AND NOT LIKE 10 个子串`。若 V4.4 §6 规范命名后，名称**不含 "Gucci"** 或**含任一排除子串**，商品上架瞬间即**掉出 Gucci-Sneakers 分类** |
| **触发条件** | 起名时按 V4.4 品牌前置规范重写，未对照排除表 |
| **后果** | 商品上架但不在目标分类 → 分类页看不到 → 等于没上架。**且不会有任何报错** |
| **具体高危样本** | ①**#21 `adidas Gazelle Gucci Original GG`**：若按品牌前置改写成 `adidas Gazelle ...` 而未保留 "Gucci"，直接掉出；②任何含 **`Bag`** 子串的名称（如 Gucci Ophidia **Bag**）；③含 `Scarf`/`polo`/`shirt` 的配件 |
| **防御** | 命名后**强制跑条件模拟器**：断言 `name.lower().find('gucci')>=0` 且 10 个排除词**全部不命中**（按子串、去大小写，取最严口径）；不通过则改到通过 |
| **检测** | 上架后重读分类成员，比对 27 个 PID 是否全在 |

> 注：I1 未确认 `nlk` 是否区分大小写。**防御按最严口径**（不区分大小写做子串匹配），代价是可能过度保守，但可避免静默掉类。

### C2 — slug 撞车

| 项 | 内容 |
|---|---|
| **失效模式** | 15 款 Screener 相似，若新 slug 只用 `gucci-screener-<颜色>`，多款同配色会撞车，后者覆盖前者 |
| **触发条件** | slug 生成未含唯一标识 |
| **后果** | URL 互相覆盖，两商品指向同一页 |
| **防御** | slug 必须含**完整 SKU 串**（`570443-9sfr0-5270`）保证唯一；生成后跑全局唯一性检查 |
| **检测** | 27 个 slug 去重后数量必须 = 27 |

### C3 — slug 变更的 301 与旧链接

| 项 | 内容 |
|---|---|
| **失效模式** | 25 款 slug 从脏串变为干净串。平台行为（旧 URL 仍 200）为 skill 记载，**未本次验证** |
| **触发条件** | 依赖未验证的平台行为 |

| **检测** | 变更后 Playwright 实测旧 URL 状态码 |

## 8. 防御性执行改版：八道 Gate

原方案（线性：生成 → 写入 → 上架）**不成立**。改为带 Gate 的流程，每个 Gate **失败即停**：

```text
Gate 0  快照     27 款全字段落盘（回滚依据）        ← 缺失
  
Gate 1  实体锁定 图 + SKU + Tier1-4 来源三方交叉
                 TypeSafe/Jev 判 Exact Entity
                 冲突 → HOLD（不出 SEO）            ← 依赖 TypeSafe key
  
Gate 2  命名合规 断言：含 "Gucci" + 10 排除词零命中
                 断言：slug 全局唯一（含完整 SKU）
                 [C1/C2 的唯一防线]                 ← 本 Gate 可立即实现
  
Gate 3  内容合规 黑名单正则阻断（pkgod/1:1/replica…）
                 断言 Content 仅含 img
                 断言 关键描述 h2×1 + li×5
                 断言 无 dripsneakers.net 残留
  
Gate 4  价格确认 BasePrice/MarketPrice 语义确认      ← 需用户确认
  
Gate 5  Canary   单款写入 + 上架 + Playwright 前台验收
                 showCount 必须 9 → 10
  
Gate 6  批量     ≤7 款/批，逐款读回 + 进度落盘
                 每批后重读分类 showCount
  
Gate 7  验收     Playwright 前台 27 款
                 title/h1/canonical/5li/ALT/JSON-LD
                 分类成员比对 27 PID 全在
```

**Gate 2 与 Gate 3 是纯确定性检查，不依赖任何外部服务，现在就能实现并测试。**

## 9. 如果只能防五条

1. **A1 实体误判** — 三重交叉 + HOLD，宁可少做不可做错
2. **C1 掉出分类** — 命名条件模拟器，断言式拦截
3. **B3 上架翻回** — 禁止即时读回作为判据，只点一次，以重载后为准
4. **E1 `BasePrice=0`** — 上架前必须确认价格语义
5. **A4/A5 违禁词与死链** — 阻断式扫描

## 10. 结论

| 问题 | 结论 |
|---|---|
| 原方案（生成→写入→上架）可行吗？ | **不可行**，缺少 4 类静默失败防线 |
| 最大风险是什么？ | 不是"写失败"，而是**"成功写入错误产品"**，且 15 款 SKU 命名使误判概率显著升高 |
| 现在能立刻做的是什么？ | Gate 0（快照）、Gate 2（命名合规）、Gate 3（内容合规）——均为确定性检查，**不依赖 TypeSafe key** |
| 卡住的是什么？ | Gate 1 依赖 TypeSafe key（未提供）；Gate 4 依赖用户确认价格语义；Gate 5+ 依赖写入授权与门禁解除 |
| 27 款会不会最终大部分 HOLD？ | **存在这个可能**。A2（图-SKU 一致性）无法闭环时，按 V4.4 只能 HOLD。应以「HOLD 清单 + 通过清单」双产出替代"27 款全过"的预期 |
