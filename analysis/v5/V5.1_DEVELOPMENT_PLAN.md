## 一、问题定位

### 当前两个 BLOCKER

| # | 模块 | 问题 | 影响 |
|---|------|------|------|
| 1 | `v5_vision.py` | Placeholder，`observations=[]` 为空 | Layer 3 无视觉证据，无法判断颜色/图案 |
| 2 | `_resolve_entity()` | 仅检查品牌名+图片数量，无交叉验证 | 所有新商品停在 CANDIDATE，永远无法 PASS |

### 根因分析

不是 Prompt 问题，是**系统架构问题**：
- Vision Observer 没有接入多模态模型
- Entity Resolver 没有调用外部数据源做交叉验证
- 两者都是"应该调用 LLM 但没接"的半成品

---

## 二、设计原则

### 铁律（写入方案，不可违反）

1. **不修改任何 [核心] 文件**：`v5_entity_state.py`、`v5_pdp_generator.py`、`v5_writer.py`、`v5_snapshot.py`
2. **保持所有接口合约**：`observe_images()` 签名不变，`generate_seo_payload()` 输入不变
3. **Evidence 是只读注入**：LLM 输出写入 `entity_state["visual_observation"]` 和新增字段，不改变状态机结构
4. **PASS 条件硬编码在 Orchestrator**：不在 LLM 返回里决策状态，由代码判断

### 4.3 PASS 判定逻辑（在 Orchestrator 中新增函数）

```python
def evaluate_evidence_pass(entity_state: dict) -> dict:
    """
    评估证据是否满足 PASS 条件
    返回: {"pass": bool, "gaps": List[str], "details": dict}
    """
    evidence = entity_state.get("v5_evidence", {})
    gaps = []

    # 检查品牌
    brand = evidence.get("identity", {}).get("brand", {})
    if not brand.get("verified") or brand.get("confidence", 0) < 0.90:
        gaps.append("brand_not_verified")

    # 检查型号
    model = evidence.get("identity", {}).get("model", {})
    if not model.get("verified") or model.get("confidence", 0) < 0.80:
        gaps.append("model_not_verified")

    # 检查产品类型
    silhouette = evidence.get("visual", {}).get("silhouette", {})
    if not silhouette.get("observed") or silhouette.get("confidence", 0) < 0.85:
        gaps.append("product_type_not_confirmed")

    # 检查颜色
    color = evidence.get("visual", {}).get("base_color_visual", {})
    if not color.get("observed") or color.get("confidence", 0) < 0.80:
        gaps.append("colorway_not_confirmed")

    # SKU 特殊处理：未验证 → OMIT，不阻塞 PASS
    sku = evidence.get("identity", {}).get("sku", {})
    if sku.get("verified") and sku.get("confidence", 0) < 0.95:
        gaps.append("sku_not_verified_to_threshold")

    return {
        "pass": len(gaps) == 0,
        "gaps": gaps,
        "details": {
            "brand_confidence": brand.get("confidence"),
            "model_confidence": model.get("confidence"),
            "color_confidence": color.get("confidence"),
            "sku_decision": sku.get("decision", "unknown")
        }
    }
```

### 5.2 各模块职责

#### evidence/evidence_schema.py

**职责**：定义 Evidence Schema + PASS 判定逻辑

**导出**：
- `PASS_REQUIREMENTS` 常量
- `evaluate_evidence_pass(state) -> dict`
- `build_evidence_schema() -> dict`（空模板）

**不依赖**：任何 LLM API，纯逻辑层

#### evidence/vision_provider.py

**职责**：调用多模态模型，提取视觉观察

**接口**：
```python
def observe_images(
    image_urls: List[str],
    product_name: str,
    model: str = "openai-gpt4o"
) -> Dict[str, Any]:
    """
    输入：图片 URL + 产品名称
    输出：Visual Evidence（符合 evidence_schema）

    支持的 model:
    - "openai-gpt4o"：GPT-4o Vision API
    - "mock"：返回预设观察结果（测试用）
    """
```

**关键行为**：
- 如果 model="mock"，返回预设观察（用于单元测试）
- 如果 model="openai-gpt4o"，调用 API 并解析 JSON 输出
- 输出严格符合 Visual Evidence Schema

#### evidence/entity_resolver.py

**职责**：调用 LLM 进行实体交叉验证

**接口**：
```python
def resolve_entity(
    snapshot: dict,
    visual_evidence: dict,
    model: str = "openai-gpt4o"
) -> Dict[str, Any]:
    """
    输入：Product Snapshot + Visual Evidence
    输出：Identity Evidence（符合 evidence_schema）

    支持的 model:
    - "openai-gpt4o"：GPT-4o API
    - "mock"：返回预设识别结果（测试用）
    """
```

**关键行为**：
- 生成搜索查询（品牌 + 型号 + 颜色）
- 调用 LLM 执行搜索 + 交叉验证
- 输出 Identity Evidence

#### evidence/source_validator.py

**职责**：验证外部来源的可信度

**接口**：
```python
def validate_source(source_url: str) -> dict:
    """
    输入：来源 URL
    输出：验证结果 {trusted: bool, source_type: str, confidence: float}
    """
```

**支持的 source_type**：
- `"stockx"`：StockX 官网
- `"goat"`：GOAT 官网
- `"brand"`：品牌官网
- `"dripsneakers"`：Drip Sneakers 内部页面
- `"unknown"`：无法识别的来源

## 六、Orchestrator 改造计划（最小改动）

### 6.1 改造点 1：替换 `_resolve_entity()` 方法

**当前**（v5_orchestrator.py 第 177-206 行）：
```python
def _resolve_entity(self, ...):
    # 仅检查品牌名和图片数量
    if not has_brand: → HOLD
    if img_count < 3: → VERIFY
    else: → CANDIDATE
```

**改造后**：
```python
def _resolve_entity(self, product_id, entity_state, snapshot, visual_fp):
    # 1. 加载 LLM Evidence Layer
    from evidence.entity_resolver import resolve_entity

    # 2. 调用 LLM 实体解析
    identity_evidence = resolve_entity(snapshot, visual_fp)

    # 3. 注入到 entity_state
    entity_state["v5_evidence"] = {
        "visual": visual_fp,
        "identity": identity_evidence,
        "collected_at": datetime.utcnow().isoformat() + "Z",
    }

    # 4. 评估 PASS 条件
    from evidence.evidence_schema import evaluate_evidence_pass
    evaluation = evaluate_evidence_pass(entity_state)

    if evaluation["pass"]:
        entity_state = update_entity_status(entity_state, EntityStatus.PASS, "Evidence pass: " + str(evaluation["details"]))
    elif evaluation["gaps"]:
        entity_state = update_entity_status(entity_state, EntityStatus.CANDIDATE, "Evidence gaps: " + str(evaluation["gaps"]))
    else:
        entity_state = update_entity_status(entity_state, EntityStatus.VERIFY, "Evidence incomplete")

    return {"entity_state": entity_state, "evaluation": evaluation}
```
