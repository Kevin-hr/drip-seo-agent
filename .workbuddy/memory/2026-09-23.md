### 接口契约（实测）

```
POST https://api.typesafe.ai/v1/systemone
Authorization: Bearer <API_KEY>
{"state": <string|object|array>, "model": "jev-latest", "questions": {<id>: <Question>}}
```
- Question 三型：`noul`（instructions + criteria{true,false}）/ `choice`（instructions + criteria{option:desc}，≤255 选项）/ `score`（criteria 为有序数组，2–10 级）
- 回答：`noul` 返 `{noul: 0..1}`；`choice` 返 `{choice, probabilities, confidence}`；`score` 返 `{score, legend, probabilities, confidence}`
- 实测模型版本 `jev-1.13.0`；错误码 401 / 422 / 429 / 529（429/529 需指数退避）

### 关键教训（TypeSafe 使用，跨项目可复用）

1. **提问陷阱：引导性问题会制造自相矛盾的答案。** 同一 state 连问 "是否含不受支持宣称"（答 clean 0.75）与 "如果有问题，是哪部分"（答 reps phrase 0.71）→ 后者是引导式，没有给模型真正的"没问题"出路，被迫挑一个。**结论：禁止设计"如果…那么…"型被迫选择的问题**；可疑结论必须用**独立、非引导**的问法复核。
2. **问题措辞决定置信度质量。** 同一判定意图，模糊表述得 conf 0.42，具体化（指明是"侧板图案/织带色/鞋底/主色"四选一）后升到 **0.83**。低置信先怀疑自己的问题，别先怀疑模型。
3. **实体判定不得混入"我们名字对不对"。** 首次设计把两者混在一个问题里 → `same_entity` 得 0.55（被旧名污染）。拆成独立问题后信号清晰（旧名 0.04）。
4. **不要拿低置信判定做决策**（<~0.6 一律走人工复核路径）。
5. **政策/词表类检查必须放代码，不能交给概率模型。** `meta_no_unsupported_claim` 对**完全相同的文案**三次给出 0.15 / 0.75 / 0.17 —— 它是词表匹配规则，不是语义判断。已从 Jev 移到 Gate 3 的确定性黑名单正则。
6. **语义软项不作硬门禁。** `kd_sentence_matches_photo` / `details_five_high_value` 等偏风格评分只作改进提示；对应的**结构**要求（1 句不重复品名、恰好 5 行属性）由 Gate 3 确定性校验。混用会把正常 PDP 误拦。
