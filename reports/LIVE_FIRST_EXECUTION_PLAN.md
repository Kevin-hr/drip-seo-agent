## 4. URL Strategy — DECISION REQUIRED (D2)

This is the single most important decision before execution.

### Option A — Keep existing URL (zero SEO risk)

**What happens:** Set `migrate_url: false` (or omit). The V44Composer stability
rule keeps the existing slug because `top-quality` is harmful, so the composer
WILL flag `url_change_required=true` and produce a `redirect_from`.

**Wait — re-examine:** The existing slug `Top-Quality-Thom-Browne-…-Grown`
contains `top-quality`, which is in the `HarmfulSlugTokens` regex. This means
`HasHarmfulSlugToken` returns `true`, and the composer will ALWAYS derive a new
slug regardless of `migrate_url`. There is no "keep" option without a code
change to add a `keep_existing_slug` override.

**Implication:** The current code cannot keep the old URL — it will always
propose migration. To keep the old URL, you must either:

  - (A1) Add a `keep_existing_slug: true` fact that overrides the harmful-token
    check, OR
  - (A2) Manually edit the slug field in the SEO dialog back to the original
    value after the plan is generated (ad-hoc, not recommended).

**If Option A is chosen via A1:** The slug stays
`Top-Quality-Thom-Browne-4-Bar-Stripe-Jersey-Stitch-Tee-Grown`.
No 301 needed. But the URL violates V4.4 §10 (harmful slug residue).

### Option B — Migrate to clean slug (V4.4 compliant)

**What happens:** The composer derives `thom-browne-4-bar-stripe-jersey-stitch-tee-brown`.
The plan records `url_change_required=true` and
`redirect_from=https://www.dripsneakers.org/Top-Quality-…-Grown`.

**What the bridge does NOT do:** The bridge does not create a 301 redirect.
The bridge records `redirect_from` in the plan, but no component owns the 301
lifecycle.

**What must happen outside the bridge:**

1. After the write, the old URL `https://www.dripsneakers.org/Top-Quality-…-Grown`
   must be configured to 301 redirect to the new URL.
2. This is a **site-level infrastructure task** — it must be done in the
   MrShopPlus admin, server config, or CDN level.
3. Until the 301 is in place, the old URL will return 404 (the slug changed in
   the backend, so the old path no longer resolves).

**Portfolio implication (R6):** 187 products carry harmful slug tokens. All
will trigger `URL-10`. A migration policy for one product should be consistent
with the plan for the other 186.

### Decision matrix

| | Option A (keep) | Option B (migrate) |
|---|---|---|
| V4.4 compliant | No (harmful slug) | Yes |
| 301 required | No | Yes (manual, outside bridge) |
| SEO risk | Low (URL stable, but slug noise) | Medium (301 gap if not done immediately) |
| Code change required | Yes (add keep_existing_slug) | No |
| Portfolio precedent | Defer migration for all 187 | Start migration, need 301 policy |

## 5. Entity Decisions

### D1 — Name token "Grown"

**Context:** The backend name ends with `Grown`. Visual inspection of the
product photographs shows a deep/chocolate brown garment. No Tier 1–4 source
attaches `Grown` as a Thom Browne colourway. The sibling product
`536027551814932` is named `…Medium Brown` but photographs as light beige —
backend colour naming is systematically unreliable.

**Options:**
- (a) Drop `Grown`, use descriptive colourway `Brown` — consistent with the
  `Black Red` / `Blue` style used in the previous Air Jordan batch.
- (b) `HOLD` the product — consistent with the `Bleached Coral` precedent.
- (c) Supply the official colourway name (requires research evidence).

**Recommendation:** (a) — `Brown` is visually verified, matches the product
photograph, and follows the existing naming convention.

### D2 — URL migration

See §4 above. This is the gating decision.

**Recommendation:** Option B (migrate), but ONLY after the 301 redirect
mechanism is confirmed and ready to deploy immediately after the write.
If the 301 cannot be placed within the same session, do not execute.

### D3 — Product Name correction

**Context:** The backend Product Name is
`Thom Browne 4 Bar Stripe Jersey Stitch Tee Grown`.
The proposed V4.4 Product Name is
`Thom Browne 4-Bar Stripe Jersey Stitch Tee Brown`.
This removes `Top Quality` (which is not in the name field but in the slug)
and replaces `Grown` with `Brown`.

**Options:**
- (a) Write the full V4.4 Product Name (`…Tee Brown`) — corrects the name.
- (b) Write only SEO fields, leave Product Name as `…Tee Grown` — minimises
  change surface but leaves the H1 and JSON-LD `name` inconsistent.

**Recommendation:** (a) — V4.4 requires `name`, `H1`, and JSON-LD `name` to be
consistent. A partial write would fail the frontend auditor.
